# GENJE source register and creative-work record templates

**Status:** DOCUMENTATION TEMPLATE — no sources, collaborators, performances or rights are asserted by this file.

GENJE documents living culture and authored practice. Preserve the distinction between a primary source, a scholar's interpretation, an artist's interpretation and the repository author's own reading. A source's existence does not prove every claim attributed to it.

## 1. Research source register

Create one record per source. Do not combine unrelated interviews, recordings or editions into one entry.

| Field | Record |
|---|---|
| Source ID | Stable identifier, e.g. `GENJE-SRC-0001` |
| Source type | Interview / recording / dictionary / scholarship / score / dataset / field note / other |
| Creator or speaker | Exact credited name or “not stated”; do not guess |
| Title / description | Exact title where available; otherwise neutral description |
| Publisher / custodian | Institution, publisher, archive or person |
| Date | Publication, recording or interview date; mark unknown |
| Access date | Date the source was consulted |
| Locator | DOI, stable URL, catalogue ID, archive reference or private controlled location |
| Claim supported | Specific, bounded proposition this source supports |
| Evidence type | Primary / secondary / tertiary / contextual |
| Context and limits | Region, community, period, genre, sample and known limitations |
| Rights / access | Licence, permission, access conditions or unknown |
| Confidence | Direct / corroborated / provisional / disputed |
| Related records | Other source IDs and the exact relationship |

### Source handling rules

- Quote only what is needed; retain page, timestamp, track or section locators.
- For interviews and field recordings, record consent, purpose, retention, access and permitted publication separately from the transcript.
- Do not turn a single speaker's account into a universal cultural statement.
- For language claims, distinguish attested usage, dictionary gloss, contextual slang, artist interpretation and etymological hypothesis.
- Record disagreement and uncertainty rather than silently harmonising sources.
- A public URL is not a rights grant. Check licence and reuse conditions.

## 2. Creative-work record

Use one record for each track, performance, choreography, audiovisual work, livecoding patch, workshop or commissioned work.

| Field | Record |
|---|---|
| Work ID | Stable identifier |
| Working / release title | Current title and any prior title |
| Form | Music / movement / livecode / audiovisual / performance / workshop / other |
| Status | IDEA / STUDY / REHEARSAL / RECORDED / REVIEW / RELEASED / WITHDRAWN |
| Author and contributors | Names, roles and requested credit |
| Concept and context | Artist-authored description; identify interpretation as interpretation |
| Tools and versions | Hardware, software, versions, patches and licences actually used |
| Inputs and sources | Source IDs, samples, references and permissions |
| Process record | Date, venue/context, setup, rehearsals and changes |
| Rights | Composition, recording, performance, samples, visuals and distribution |
| Consent | Participants, scope, duration, withdrawal/contact process |
| Release scope | Private study / documentation / public release / licensed use |
| Reproducibility | Files, instructions, dependencies and known gaps |
| Approval | Named human reviewer, decision, date and evidence |

## 3. Movement and livecoding experiment log

For each bounded study, state:

1. Research question and why existing tools or notation do not already answer it.
2. Participants, roles and consent boundaries, if any.
3. Movement/music representation and timebase.
4. Exact tools, versions, protocols and hardware actually used.
5. Input/output path, sampling or event rate, synchronization and latency method.
6. What was measured, what was observed and what was not measured.
7. Failure cases, transformation loss and accessibility considerations.
8. Data retention, deletion and publication decision.
9. Reproduction steps and independent review status.

Do not imply motion capture, realtime interoperability, a working converter or a completed performance unless the corresponding evidence exists. No person scoring, covert capture or identity matching.

## 4. Review checklist

- [ ] Claims are linked to source IDs and precise locators.
- [ ] Artist interpretation is labelled as such.
- [ ] Contributors and creators are credited accurately.
- [ ] Rights and consent cover the intended use.
- [ ] Software and source versions are recorded.
- [ ] Status reflects the actual maturity of the work.
- [ ] Private participant information is excluded from public records.
- [ ] Any unresolved issue is visible, not silently marked complete.
